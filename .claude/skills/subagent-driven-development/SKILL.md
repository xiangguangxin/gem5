# 团队协作

使用前读取 [协作契约](../../references/team-contract.md)，角色定义见 `.claude/agents/`。先确认宿主真实支持对应 Agent 调用；没有工具则顺序承担必要职责并注明未做独立评审，不虚构启动成功。

## 选择角色

- 设计不清或跨组件：cto 分析，red-team 检验关键假设，再实施。
- 实现已明确：developer 实现，red-team 检查高风险路径，verifier 验证实际产物。
- 文档任务：tech-writer 整理，主执行者或 verifier 检查来源、链接和图；通常不需要代码实现阶段。
- 并发、生命周期、协议、公共接口变更重点评审；按风险选流程，不单凭 diff 行数。

## 交接与依赖

每次派发包含原需求、授权范围、验收、相关路径、起始状态和上轮完整问题。给独立任务明确文件归属；同一文件和依赖变更顺序执行。实际调用方式遵循当前宿主，不假设所有环境都有同名 Agent API。

设计 → 设计评审 → 必要文档 → 实现 → 实现评审 → 验证。未通过回交责任角色；反馈保留位置、反例和命令证据。空结果、超时、无效结构不算通过。评审提出的问题逐 ID 关闭，阻断问题不由实施者自行接受风险。

默认最多三轮自动修订，仍未解决则返回问题、证据和需要的决定，不继续下一阶段。实现每次变化后，重新审受影响部分并验证；发布、提交和推送按用户既有授权，不是团队流程默认动作。

## 交付

主执行者整合文件清单、行为、真实验证、限制与剩余项。脚本 `.claude/workflows/agent-team.js` 是可选宿主模板，不自带 Agent SDK；接口与模拟测试见协作契约。它保证流程分支检查，不能证明 Agent 报告真实性。
