# Bug Fix

## 系统化修复 Bug

核心原则：**根治，不打补丁**（证据先行、100% 定位根因）。

流程：

复现 → 最小可复现用例 → 定位根因 → 全面分析影响 → 修复 → 回归

## 1. 复现

先稳定复现，复现不了就继续收集证据，不要开始改代码。

- 记录触发条件、输入、环境、时序。
- 复现要确定：同样输入必现同样错，不是偶发。

## 2. 最小可复现用例

把复现压到最小：去掉无关代码 / 输入，直到再删一步就复现不了。

- 最小用例是定位根因的"手术刀"，隔离出真正的触发条件。
- 最小化的过程本身就能排除大量无关假设。

## 3. 定位根因

顺着数据流追溯到源头，不停留在症状处。

- 从出错点逆向追踪：这个值是错的，是它本身错，还是上游传错了？
- 逐层追问，直到找到源头。
- 数据流一时追不到底时，提出假设 → 验证 → 修正假设，别陷入猜测式修改。
- 100% 定位根因：能一句话说清"为什么错、为什么以前没发现"。

## 4. 全面分析影响

修复前先想清楚影响面：

- 根因还影响了哪些路径 / 模块 / 调用方？
- 是单一入口还是共用底层？改动会不会波及其他功能？
- 有没有同类错误模式在别处也出现？

## 5. 修复

修根因，不掩盖症状。

- 修复要能解释"为什么这是根因的解法"，不是"碰巧不报错"。
- 小步改：改 → 编译 → 测试，别一次改一堆。

## 6. 回归

加防护测试，防止再犯。

- 把最小可复现用例固化成测试，确认修复后通过。
- 跑全量回归，确认没破坏别的功能。
- 提供测试输出作为证据，再宣布完成。
