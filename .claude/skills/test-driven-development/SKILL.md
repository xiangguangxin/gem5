# Test Driven Development

## 测试驱动开发

核心循环：

RED

测试失败

GREEN

最小实现

REFACTOR

优化代码

测试应该定义需求，而不是事后验证。

## 选择有意义的测试

新增或修复可执行行为时，先构造能暴露错误的正常/边界场景，确认失败原因来自目标行为，再最小实现并复查相关回归。测试输入输出、状态和错误路径，而不是只断言实现中的字符串存在。

纯文字、格式或低影响可逆调整采用相应检查，不强制制造单元测试。测试环境不可用时说明阻碍，不谎称已完成 RED/GREEN。已有测试通过后，只有新修改或风险才需要扩大验证。
