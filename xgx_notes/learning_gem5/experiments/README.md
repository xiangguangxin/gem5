# 性能实验与模型校验

先完成[内存微基准分步实验 B](memory_lab.md)，再用本文规范扩展其他实验。

## 先提出可证伪的问题

把“研究内存性能”改成“固定 CPU 和工作集时，提高 DMA outstanding 是否能增加有效带宽，何时饱和”。预先写出预期、控制变量与反例，完成后保留不符合预期的结果。

## 最小实验矩阵

| 负载 | 控制条件 | 扫描项 | 重点观察 |
|---|---|---|---|
| 顺序读/写流 | 固定数据量、访问宽度与 CPU | 工作集、并发度 | 有效带宽、实际流量、队列 |
| 依赖指针追逐 | 每次地址依赖上次结果 | 工作集、内存延迟 | 平均访问时间，避免当作峰值带宽测试 |
| 重复访问数组 | 固定访问序列 | 容量、相联度 | miss 与容量/冲突变化 |
| DMA 拷贝 | 固定总字节、块大小 | outstanding、内存配置 | 完成时延、在途数、背压 |
| GEMM | 固定 M/K/N、精度与正确性 | 阵列、SRAM、DMA | 计算与搬运重叠、端到端时间 |

微基准需防止编译器删除工作，并保存源码、编译命令、二进制哈希。CPU 顺序流不保证压满内存；要研究峰值需控制并发请求，并可对照 `src/cpu/testers/traffic_gen/` 的流量发生器。

## 测量协议

1. 固定 commit、build、ISA、编译选项、workload、随机种子和输入。
2. 明确 ROI；决定是否预热 Cache、是否包含初始化与结果写回。重置统计不会清空 Cache。
3. 在选定边界 reset/dump 统计，记录转储次数。使用 Python `m5.stats.reset()/dump()` 或工作负载标记时，先确认控制路径确实触发。
4. 每组实验使用独立输出目录，保存配置、命令、stdout/stderr 和退出原因。
5. 先校验输出与完成状态，再提取统计；多段 `stats.txt` 按 ROI 选择，不能直接拼加累计值。
6. 单变量扫描确认趋势后再组合。随机负载使用多个种子并报告离散程度；确定性运行无需机械重复。

## 指标定义

- IPC = ROI 内提交指令数 / 对应 CPU 周期数。多核需说明按核报告还是聚合，不能混用 micro-op 与 instruction。
- 有效带宽 = 应用有效字节 / ROI 时间；内存总线流量还可能包含取指、预取、写回及额外块传输。
- miss rate = 同一口径的 miss / access，明确缓存层级与读写类型。
- 平均时延之外记录分布或尾部；系统吞吐与单请求时延不能互相替代。
- CPU IPC 是辅助指标，NPU 项目应优先看任务端到端时延、吞吐和计算/搬运利用率。

统计名称依 CPU 和内存模型变化。先在实际 `stats.txt` 中确认对象路径、单位和描述，缺失项报告为缺失，不能填零。结合[指标笔记](../../gem5_benchmark_and_stats.md)阅读。

## 模型校验与停止条件

先用固定延迟模型检查单笔请求，再用有限并发验证排队与背压；最后接复杂 DRAM 或 NPU。

- 纯传输且忽略重叠细节时，数据量 D、带宽 B 给出的传输下界为 D/B；实际系统还受启动、延迟和并行度影响。
- GEMM 约有 2MNK 次运算（一次 MAC 按两次操作计），计算下界由约定的峰值算力给出。
- 重叠执行时不能简单把所有时间相加；应同时观察阶段区间和端到端时间。
- 结果超过理论上限时先查单位、ROI、流量口径和峰值定义。

小规模验证通过后再扩大扫描。失败结果应带状态保留，不进入正常性能均值。
