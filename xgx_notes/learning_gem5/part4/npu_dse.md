# NPU 接入、模型校验与 DSE

## 最小架构与范围

```text
CPU / 提交驱动 ── 控制互联 ── NPU 寄存器
                                  │
                              SRAM / PE
                                  │
CPU Cache ── 共享互联 ─────────── DMA
                 │
              MemCtrl
                 │
             DRAM / HBM
```

控制和数据通路可以共享互联，但需要分别定义。先完成单 NPU、单任务、共享内存闭环；多 NPU、详细 NoC、真实驱动作为后续扩展。

对照[已有 NPU 集成方案](../../gem5_npu.md)，重新检查外部模型的源码、依赖及已完成状态，不能仅依据笔记中的“现状”判断可用性。

## 接入清单

1. 定义 GEMM 的 M/K/N、数据类型、布局、步长、累加规则与参考结果；说明是否使用真实数据或只有 timing。
2. 明确提交参数和地址空间；记录 DMA 读入、计算、DMA 写回、完成通知的时间点。
3. 区分片上 SRAM、共享内存和 NPU 私有内存；保证一次访问只由选定的存储模型服务。
4. 说明 CPU Cache 与 DMA 的一致性策略，并单独验证数据可见性。
5. 检查任务开始/结束与 ROI 的边界，确认结束包含所有输出写回。

## 分层校验

| 层次 | 校验方式 |
|---|---|
| PE / 计算 | 小矩阵参考结果；检查 fill / steady / drain，维度不足时的利用率 |
| SRAM | 容量边界、访问带宽、bank/端口约束是否被模型表达 |
| DMA | 小块正确性、并发上限、背压与有效带宽 |
| 内存 | 单请求延迟、持续流量饱和点、争用下的变化 |
| 端到端 | 对照独立 NPU 模型，解释时间差异来自哪些系统开销 |

仅 timing 模型应明确数值正确性由何处独立验证。测量容差应在比较前确定，模型改变后重新校验。

## DSE 计划

先选择一个目标，例如“在 SRAM 容量上限与目标时延下最大化吞吐”。面积/功耗约束必须有估算依据，不能把 PE 数量直接当作准确面积。

| 参数 | 第一轮建议 | 同时记录 |
|---|---|---|
| 阵列维度 | 基线的较小/基线/较大三个合法值 | 理论算力与实际利用率 |
| SRAM 容量 | 能容纳不同 tile 的配置 | tiling、搬运量、溢出策略 |
| DMA outstanding | 1、2、4、8，受实现上限约束 | 在途数、队列等待 |
| 内存配置 | 两至三组可解释的控制器/介质参数 | 理论上限与实际带宽 |

参数取值需以实际实现为准。先固定 GEMM 做单变量扫描，再在代表性矩阵上做有限组合；改变 SRAM 导致 tiling 改变时，把调度变化一起记录。

每次运行生成唯一 ID，保存完整参数、commit、输入、退出原因、正确性、ROI 和原始统计。设置超时与失败状态，汇总时排除失败点并报告失败原因。

## 分析与交付

- 画时延/吞吐随单参数的曲线，并用 PE、DMA、内存统计解释拐点。
- 对重叠执行绘制阶段时间线，区分等待与有效工作。
- 多目标时报告互不支配的 Pareto 候选，而非宣布一个无条件最优配置。
- 没有每次操作/访问的能耗参数和校验方法时，只报告性能与活动量。

最终提交可运行配置、模型变更、自动运行/提取脚本、数据与报告。先复现基线，再检查改进在多个 workload 上是否成立。

## 分步实验 F：先解释一个任务，再扫描一批配置

**重点逻辑：功能正确 → 子模型可解释 → 端到端时间可解释 → 参数扫描。改变参数后需要同时核对调度、流量与利用率。**

### F1：固定一个足够小的 GEMM

先取模型支持的合法小尺寸，例如 M=N=K=16；使用固定种子、明确数值范围和参考实现。固定数据类型及累加类型，整数按规定的溢出规则比较，浮点提前约定绝对/相对误差。记录输入输出与参考结果。

若模型只输出 timing，单独验证算子映射与运算量，并将数据正确性未被端到端覆盖写入报告。

### F2：画一个任务的时间线

记录任务接受、第一/最后一笔读完成、计算开始/结束、最后写完成、done 被观察的时间。存在流水重叠时，按 tile 记录，不把“最后读完”误当成“计算才开始”。先用单 tile、禁用重叠得到简单基线，再启用 double buffering。

核对完成时间是否包含所有输出写回。CPU 提交开销、NPU 忙碌时间和应用端到端时间分别报告。

### F3：做两类极端负载

取能放入片上存储且复用较好的负载，再取搬运占比较高的负载；尺寸以实际 SRAM 与 tiling 能力为准。估算运算量 2MNK 与实际读写量，检查阵列填充/排空、SRAM 限制及 DMA 等待。

理想重叠的粗略下界可用 `max(计算下界, 搬运下界)` 参考；没有重叠的简化情况接近相加，实际还包含依赖与调度。用阶段日志解释差距。

### F4：只扫 DMA 并发度

固定阵列、SRAM、GEMM 和内存，运行 outstanding=1/2/4/8 中实现支持的值。每点保存完整配置，不只保存改动项。表中至少填端到端时延、有效字节、DMA 等待、在途峰值和正确性状态。

预期可能先下降后饱和；如果并发度增加但在途峰值不变，优先检查发起逻辑或其他限制。

### F5：扫描计算与存储能力

恢复基线，分别只改阵列或 SRAM。阵列扩大后检查低利用率是否来自小矩阵、fill/drain 或供数不足。SRAM 改变后记录 tile 与搬运量变化；这是软件调度与硬件参数共同变化，结论需要说明。

随后选择少量代表点做组合实验，不直接运行巨大笛卡尔积。至少覆盖两类不同瓶颈的 workload。

### F6：汇总与选择

为每点记录 `run_id/workload/完整参数/commit/status/正确性/ROI/指标路径`。失败与超时单独列出；单位统一后生成曲线。每个“更快”结论至少对应一项支持它的行为证据，如 DMA 等待下降或计算利用率上升。

**验收**：别人依据记录能重跑基线；你能解释一个改进点、一个无效增配点和一个性能拐点。完成这些后再考虑多 NPU 与 NoC。
